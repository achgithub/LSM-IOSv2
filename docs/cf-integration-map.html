Architecture reference · LSM-IOSv2

Everything the app says to Cloudflare, and everything Cloudflare says back

Three Worker codebases, three D1 databases, one shared R2 bucket, region-scoped KV, and a Pages-hosted PWA — mapped end to end from the iOS Swift call sites down to the wrangler bindings. Updated 2026-08-02 after committing the custom-domain fix and tearing down the never-deployed EU authority env plus a full sweep of unused legacy v1 Cloudflare resources (see §09).

03 · iOS call sites

Everything under ios/LSM/LSM/Cloud/ plus the two config files that decide where those calls go. Each is a Swift actor — one per concern, no shared network layer.

APIClient.swiftCloud/APIClient.swift · 63 lines

One instance per league. Calls teams(), standings(), scores(), fixtures() against the league's workerBaseURL. Attaches App Attest/JWT headers via AppAttestService.shared.authorizationHeaders(). Non-2xx responses route through MaintenanceCheck.

Leagues.swiftConfig/Leagues.swift · 256 lines

Owns the league registry manifest. registryURL (line 116) is hardcoded to the workers.dev host — see finding 08.1. refreshFromRegistry() fetches, decodes, runs VersionGateCheck, and caches to disk. authorities/storefrontMap drive attest-authority resolution.

AppAttest.swiftCloud/AppAttest.swift · 296 lines

The App Attest / JWT client. authorityURL() resolves once per install from StoreKit storefront, persisted to UserDefaults, correctly falling back to the custom domain api.<region>.sportsmanager.site. Drives fetchChallenge → register → mintJWT, with one retry on a stale-registration 403. Key lives in Keychain.

SnapshotClient.swiftCloud/SnapshotClient.swift · 102 lines

Backup and publish. backup(_:id:) → PUT /backup/:id; restore(id:) → GET /backup/:id; publish(...) → POST /publish. All routed through authorityRequest(path:method:).

SubmissionsClient.swiftCloud/SubmissionsClient.swift · 251 lines

Manager-facing half of the PWA submission queue. playerBase is hardcoded to submit.sportsmanager.site — the PWA's own domain, separate from the authority API.

  • mintLink, revokeLink, revokeLinkByName → /links*
  • pushRound → POST /games/:gameToken/push, mode-agnostic payload (covers Killer)
  • listSubmissions, approve, reject, deleteGame → /games/:gameToken/submissions[...]
ManagerLifecycleClient.swiftCloud/ManagerLifecycleClient.swift · 108 lines

status() on Cloud Settings open; reportEntitlements(maxPWALinks:) once per launch and on purchase/restore; unsubscribe() when the cloud entitlement lapses; resubscribe() on renewal. Auth is X-Manager-Token only — deliberately no JWT, to keep the token out of URLs and logs.

ManagerToken.swiftCloud/ManagerToken.swift · 96 lines

No network. Keychain-backed anonymous UUID sent as X-Manager-Token by every client above. Migrates forward from a prior wrong-bundle-id Keychain service name.

MaintenanceState.swiftCloud/MaintenanceState.swift · 63 lines

No direct network. MaintenanceCheck.check runs after every client's non-2xx response, detects the shared {error:"maintenance"} 503 shape, drives the app-wide banner.

VersionGate.swiftCloud/VersionGate.swift · 73 lines

No direct network. Called only from Leagues.refreshFromRegistry(); compares the running build against the manifest's minVersion and hard-blocks the UI if stale.

GameCloudClient.swiftCloud/GameCloudClient.swift · 49 lines

Inert skeleton — every function throws CloudError.notImplemented. Pre-pivot sketch of a Layer-2 cloud-backed game state, not wired to any live route.

Outside Cloud/: PurchaseService.swift and Entitlements.swift talk to RevenueCat/StoreKit directly, never through a Worker. The only bridge is reportEntitlements forwarding the resolved tier to lsm-api. No APNs registration, no server-side receipt validation, no App Store Server Notifications webhook exist anywhere in the repo.

04 · Storage layer

One R2 bucket shared by two Workers, two D1 schemas across four (planned) databases, and per-region KV namespaces that are quietly the same namespace under three different binding names.

R2lsm-cloud-bundle

One bucket, bound identically into both lsm-worker and lsm-api, uk and eu — a backup/publish blob is self-contained and not league-scoped, so any shard can serve it.

06 · Auth mechanisms

Five schemes, layered by how sensitive the route is — from full device attestation down to a rate-limited PIN.

  1. App Attest → 15-minute ES256 JWT primary

    Enrolment once per device per authority: /attest/challenge → /attest/register, verified via CBOR-decoded attestation pinned against Apple's root CA. Per-session: /attest/assert mints a short-lived JWT, Bearer-attached to every protected call.

    Verified independently by both Workers — lsm-worker trusts JWTs from any known authority via a shared JWT_PUBLIC_KEYS kid→key map, so adding a region is a config change, not a code change. A dev bypass exists but is designed to be impossible in a release build.

  2. Anonymous device / manager tokens no login, no PII

    ManagerToken.current — client-generated UUID, Keychain-persisted, sent as X-Manager-Token. Scopes ownership of games, publish links, backups, lifecycle rows, and is the sole credential on /manager/* — deliberately kept out of JWT claims and URLs to avoid leaking into logs.

    Player tokens are a second, unrelated tier: one unguessable UUID per player, the only credential in the public /s/<token> PWA link, deliberately outside GDPR personal-data scope.

  3. Admin bearer tokens ops

    Authorization: Bearer <ADMIN_TOKEN>, region-prefixed secrets, timing-safe compared. Gate all /admin/* routes on both Workers; worker-dash holds its own copies (WRK_* prefix) to proxy actions.

  4. Cloudflare Access JWT edge + code

    Gates worker-dash at the edge (policy lives in the Zero Trust dashboard, not the repo) and is independently re-verified against the team's JWKS, RS256, audience-scoped. Fails closed on any verification failure, including an unreachable JWKS endpoint.

  5. PIN-based unlock access control, not identity

    publish_links.pin_hash/pin_salt (salted SHA-256), checked in POST /publish/:id/unlock. Brute-force protected: 10 attempts, 30-minute lockout, reset on republish.

07 · External integrations proxied through Cloudflare

football-data.org

The only upstream sports-data provider, called from worker/src/football.ts. Token stored as a region-prefixed secret, never exposed client-side. Consumed via a Provider interface designed for future multi-provider support. Licence obligation is attribution-only, shipped in Settings → About.

Cloudflare Access

JWKS fetched from audleyhome.cloudflareaccess.com to verify the ops dashboard's edge auth. Not called by the app or PWA.

No Apple App Store Server Notifications webhook, no APNs, no RevenueCat webhook are proxied through any Worker. RevenueCat/StoreKit purchases resolve entirely client-side; only the resolved maxPWALinks entitlement is reported to lsm-api.

08 · Known issues

Surfaced while tracing the touchpoints above — ordered by how directly they affect a live user or the security boundary.

critical

Leagues.swift still points at workers.dev, and a fresh install can get stuck there

worker/src/manifest.ts's move of SHARD_BASE to the custom domains is now committed (main, 2026-08-02) and deployed — confirmed live at GET uk-api.sportsmanager.site/leagues.json. But ios/LSM/LSM/Config/Leagues.swift:116's registryURL, and the bundled Resources/leagues.json, still hardcode lsm-uk-worker.sportsmanager.workers.dev. The registry refresh itself uses the stale URL, so if workers.dev is ever locked down before an app rebuild ships, existing installs have no path to discover the corrected domain. Still needs an app rebuild — sequence: rebuild first, let it propagate, only then disable workers.dev.
